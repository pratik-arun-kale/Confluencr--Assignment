# API Reference

Base URL: `http://127.0.0.1:8000/api/v1` (the health check is at `/health`, without the prefix).
An interactive version of this reference is served at `/docs` (Swagger) and `/redoc`.

## Conventions

| Topic | Convention |
|---|---|
| Format | JSON request and response bodies (`Content-Type: application/json`) |
| IDs | UUIDv4 strings |
| Money | Responses: a string with exactly 2 decimals, e.g. `"150.00"`, so no float rounding. Requests: a string or a JSON number, `> 0`, at most 2 decimals, at most `1000000000.00` |
| Timestamps | ISO-8601 in UTC, e.g. `2026-10-27T05:25:37.833935Z`, generated by the server |
| Unknown fields | Rejected with `400 VALIDATION_ERROR`. For example, sending `balance` when creating an account is an error, not silently ignored. |
| Request ID | Every response has an `X-Request-ID` header. Send your own (`[A-Za-z0-9._-]{1,64}`) to correlate logs. |

## Endpoints

| Method | Path | Description |
|---|---|---|
| `POST` | [`/accounts`](#create-an-account) | Create an account |
| `GET` | [`/accounts/{account_id}`](#get-an-account) | Get an account |
| `GET` | [`/accounts/{account_id}/balance`](#get-a-balance) | Get the current balance |
| `POST` | [`/accounts/{account_id}/transactions`](#post-a-transaction) | Post a credit or debit |
| `GET` | [`/accounts/{account_id}/transactions`](#list-transactions) | Paginated, filterable history |
| `POST` | [`/transfers`](#transfer-money) | Transfer between two accounts |
| `GET` | [`/health`](#health) | Liveness and database check |

Transactions and transfers cannot be changed or removed: `PUT`/`PATCH`/`DELETE` return
`405 METHOD_NOT_ALLOWED` or `404 NOT_FOUND`.

### Create an account

`POST /accounts`

| Field | Type | Rules |
|---|---|---|
| `name` | string | Required. Surrounding whitespace is trimmed. 1–100 characters. |

```bash
curl -X POST http://127.0.0.1:8000/api/v1/accounts \
  -H "Content-Type: application/json" -d '{"name": "Alice"}'
```

`201 Created`

```json
{
  "id": "b3329350-983e-4868-a35f-b61e41263d5b",
  "name": "Alice",
  "balance": "0.00",
  "created_at": "2026-10-27T05:25:36.652003Z"
}
```

Errors: `400 VALIDATION_ERROR` (missing/blank/too-long name, or unknown fields such as `balance`).

### Get an account

`GET /accounts/{account_id}` returns `200` with the same shape as above.

Errors: `400 INVALID_ACCOUNT_ID` (not a UUID), `404 ACCOUNT_NOT_FOUND`.

### Get a balance

`GET /accounts/{account_id}/balance`

`200 OK`

```json
{ "account_id": "b3329350-983e-4868-a35f-b61e41263d5b", "balance": "70.00" }
```

Errors: `400 INVALID_ACCOUNT_ID`, `404 ACCOUNT_NOT_FOUND`.

### Post a transaction

`POST /accounts/{account_id}/transactions`

| Field | Type | Rules |
|---|---|---|
| `type` | string | Required. `credit` or `debit` |
| `amount` | string or number | Required. `> 0`, at most 2 decimals, at most `1000000000.00` |
| `reference_id` | string | Required. 1–100 characters. Unique per account. |
| `description` | string | Optional. Up to 255 characters. |

A `credit` adds the amount to the balance. A `debit` subtracts it, and is rejected if the
balance is too low. The entry and the balance change are committed together, or not at all.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/accounts/{account_id}/transactions \
  -H "Content-Type: application/json" \
  -d '{"type": "credit", "amount": "100.00", "description": "Salary", "reference_id": "INV-001"}'
```

`201 Created`

```json
{
  "id": "775c9795-4a6b-48bd-82b1-964980394b29",
  "account_id": "b3329350-983e-4868-a35f-b61e41263d5b",
  "type": "credit",
  "amount": "100.00",
  "description": "Salary",
  "reference_id": "INV-001",
  "transfer_id": null,
  "created_at": "2026-10-27T05:25:37.833935Z"
}
```

**Insufficient balance:** `422`. Nothing is written and the balance is unchanged.

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance: available 100.00, requested 150.00",
    "details": {
      "account_id": "b3329350-983e-4868-a35f-b61e41263d5b",
      "available_balance": "100.00",
      "requested_amount": "150.00"
    },
    "request_id": "50a7deb59c204a00a74ba9717f893a8b"
  }
}
```

**Duplicate `reference_id`:** `409`. No new transaction is created and the balance is unchanged.

- If the payload is identical (a retry), the code is `DUPLICATE_TRANSACTION` and `details.existing_transaction` contains the original transaction:

  ```json
  {
    "error": {
      "code": "DUPLICATE_TRANSACTION",
      "message": "Transaction with reference_id 'INV-001' already exists",
      "details": { "existing_transaction": { "id": "775c9795-…", "amount": "100.00", "…": "…" } },
      "request_id": "67bc9001052d41b58659e150ec775065"
    }
  }
  ```

- If the same reference is reused with a different type, amount or description, the code is `REFERENCE_ID_CONFLICT` and `details` contains `reference_id` and `existing_transaction_id`.

The same `reference_id` may be used on different accounts.

Other errors: `400 VALIDATION_ERROR` (with one `details` entry per invalid field, shown below),
`400 INVALID_JSON`, `400 INVALID_ACCOUNT_ID`, `404 ACCOUNT_NOT_FOUND`,
`422 BALANCE_LIMIT_EXCEEDED`, `503 LOCK_TIMEOUT`.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      { "field": "type", "message": "Input should be 'credit' or 'debit'", "type": "enum" },
      { "field": "amount", "message": "Input should be greater than 0", "type": "greater_than" },
      { "field": "reference_id", "message": "Field required", "type": "missing" }
    ],
    "request_id": "940edc7e364046e09dead0831f095b37"
  }
}
```

### List transactions

`GET /accounts/{account_id}/transactions?type=&page=&limit=`

| Query | Default | Rules |
|---|---|---|
| `type` | (both) | `credit` or `debit`. If omitted, both types are returned. |
| `page` | `1` | Integer ≥ 1 |
| `limit` | `20` | Integer from 1 to 100 |

Results are ordered **latest first** by `created_at`, with ties broken by insertion order.
Asking for a page past the end returns an empty `data` list, not an error.

```bash
curl "http://127.0.0.1:8000/api/v1/accounts/{account_id}/transactions?type=debit&page=1&limit=1"
```

`200 OK`

```json
{
  "data": [
    {
      "id": "66cba410-6a7b-4a5a-8b9b-29170ae256c8",
      "account_id": "b3329350-983e-4868-a35f-b61e41263d5b",
      "type": "debit",
      "amount": "30.00",
      "description": "Rent",
      "reference_id": "TRF-488b63e6-fbaa-44b6-826a-4f23bd77bde1",
      "transfer_id": "488b63e6-fbaa-44b6-826a-4f23bd77bde1",
      "created_at": "2026-10-27T05:25:38.481852Z"
    }
  ],
  "pagination": { "page": 1, "limit": 1, "total_records": 2, "total_pages": 2 }
}
```

Errors: `400 VALIDATION_ERROR` (invalid `type`, `page`, or `limit`; `details[].field` names the
parameter), `400 INVALID_ACCOUNT_ID`, `404 ACCOUNT_NOT_FOUND`.

### Transfer money

`POST /transfers`

| Field | Type | Rules |
|---|---|---|
| `from_account_id` | UUID | Required. Must exist. |
| `to_account_id` | UUID | Required. Must exist and must differ from `from_account_id`. |
| `amount` | string or number | Same rules as for transactions |
| `reference_id` | string | Required. Unique per **source** account. |
| `description` | string | Optional. Copied onto both legs. |

The source is debited and the destination credited in one database transaction. Each leg is
a normal ledger entry that appears in its account's history, linked by `transfer_id`, with
`reference_id = "TRF-{transfer_id}"`. If any step fails, nothing is written.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/transfers -H "Content-Type: application/json" \
  -d '{"from_account_id": "<A>", "to_account_id": "<B>", "amount": "30", "reference_id": "TRF-001", "description": "Rent"}'
```

`201 Created`

```json
{
  "id": "488b63e6-fbaa-44b6-826a-4f23bd77bde1",
  "from_account_id": "b3329350-983e-4868-a35f-b61e41263d5b",
  "to_account_id": "3973745b-496d-4e71-b4e7-2820e77eba5b",
  "amount": "30.00",
  "description": "Rent",
  "reference_id": "TRF-001",
  "created_at": "2026-10-27T05:25:38.478037Z",
  "debit_transaction": {
    "id": "66cba410-6a7b-4a5a-8b9b-29170ae256c8",
    "account_id": "b3329350-983e-4868-a35f-b61e41263d5b",
    "type": "debit",
    "amount": "30.00",
    "description": "Rent",
    "reference_id": "TRF-488b63e6-fbaa-44b6-826a-4f23bd77bde1",
    "transfer_id": "488b63e6-fbaa-44b6-826a-4f23bd77bde1",
    "created_at": "2026-10-27T05:25:38.481852Z"
  },
  "credit_transaction": {
    "id": "3130a133-2cc9-4beb-9ab4-8612a76b6489",
    "account_id": "3973745b-496d-4e71-b4e7-2820e77eba5b",
    "type": "credit",
    "amount": "30.00",
    "description": "Rent",
    "reference_id": "TRF-488b63e6-fbaa-44b6-826a-4f23bd77bde1",
    "transfer_id": "488b63e6-fbaa-44b6-826a-4f23bd77bde1",
    "created_at": "2026-10-27T05:25:38.481925Z"
  }
}
```

Errors:

| Status | Code | When |
|---|---|---|
| 400 | `SAME_ACCOUNT_TRANSFER` | Source and destination are the same account |
| 400 | `VALIDATION_ERROR` | Invalid input |
| 404 | `ACCOUNT_NOT_FOUND` | Either account is missing (`details.account_id` says which) |
| 409 | `DUPLICATE_TRANSFER` | Identical retry; `details.existing_transfer` contains the original |
| 409 | `REFERENCE_ID_CONFLICT` | Same reference with a different payload |
| 422 | `INSUFFICIENT_BALANCE` | The source balance is too low |
| 503 | `LOCK_TIMEOUT` | Safe to retry |

### Health

`GET /health` returns `200 {"status": "ok", "database": "up"}`, or
`503 {"status": "degraded", "database": "down"}` if the database is unreachable.

## Error reference

Every error has the same shape:

```json
{ "error": { "code": "…", "message": "…", "details": null, "request_id": "…" } }
```

| HTTP | `code` | Meaning |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Body, path or query failed validation. `details` is a list of `{field, message, type}`. |
| 400 | `INVALID_JSON` | The body is not valid JSON |
| 400 | `INVALID_ACCOUNT_ID` | The account ID in the path is not a UUID |
| 400 | `SAME_ACCOUNT_TRANSFER` | A transfer names the same account on both sides |
| 404 | `ACCOUNT_NOT_FOUND` | The account does not exist |
| 404 | `NOT_FOUND` | Unknown route |
| 405 | `METHOD_NOT_ALLOWED` | Method not supported on this route (e.g. modifying a transaction) |
| 409 | `DUPLICATE_TRANSACTION` | `reference_id` was already used on this account with the same payload |
| 409 | `DUPLICATE_TRANSFER` | `reference_id` was already used for a transfer from this account with the same payload |
| 409 | `REFERENCE_ID_CONFLICT` | `reference_id` was already used with a different payload |
| 422 | `INSUFFICIENT_BALANCE` | A debit or transfer exceeds the available balance |
| 422 | `BALANCE_LIMIT_EXCEEDED` | A credit would exceed the largest storable balance (`9999999999999999.99`) |
| 500 | `INTERNAL_ERROR` | Unexpected failure. Internals are never exposed; quote `request_id` to find it in the logs. |
| 503 | `LOCK_TIMEOUT` | The account was locked by other operations for longer than `DB_LOCK_TIMEOUT_MS`. Retry; a `Retry-After` header is included. |
